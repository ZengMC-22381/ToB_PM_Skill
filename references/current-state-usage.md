# 现状业务逻辑读取模块使用说明（current-state-usage）

本文件说明如何在 `prd-writer-b2b` Skill 中使用“先读取现有业务逻辑，再撰写新 PRD”的能力。

## 1. 适用场景

当你手里已经有以下资料之一时，建议启用本模块：
- 历史 PRD
- 现有流程说明
- 会议纪要
- 旧版本功能方案
- 系统操作说明

## 2. 核心原则

### 2.1 先理解现状，再写新增需求
先从参考资料中提炼当前业务逻辑，再判断本次需求影响哪些模块、角色、流程和规则。

### 2.2 参考资料只用于参考
必须遵守：
- 参考资料不是最终交付内容
- 新 PRD 必须独立成文
- 不把参考 PRD 与新 PRD 混写
- 不大段复制参考资料原文

### 2.3 统一以 Markdown 文件交付
本模块涉及的中间产物和最终产物，都统一输出为 `.md` 文件：
- `current-state-summary.md`
- `new-prd.md`

不要把完整正文直接输出在答案中。

## 3. 推荐使用方式

### 方式一：直接读取现状并输出独立新 PRD
适合资料较清晰、需求边界较明确的情况。

示例指令：

```text
请使用 prd-writer-b2b Skill。
基于我提供的参考 PRD 理解当前业务逻辑，再输出一份独立的新 PRD。
注意：参考 PRD 仅用于参考，新 PRD 必须独立成文，并以 md 文件交付。
```

### 方式二：先输出现状摘要，再输出独立新 PRD
适合参考资料较长、版本较多或逻辑较复杂的情况。

示例指令：

```text
请使用 prd-writer-b2b Skill。
先根据参考资料输出《现状业务逻辑摘要》md 文件，
确认现状后，再输出一份独立的新 PRD md 文件。
注意：不要把参考 PRD 与新 PRD 混写。
```

### 方式三：只做现状梳理，暂不写新 PRD
适合前期需求分析阶段。

示例指令：

```text
请使用 prd-writer-b2b Skill。
先根据我提供的资料，输出一份《现状业务逻辑摘要》md 文件。
暂时不要写新 PRD。
```

## 4. 现状摘要建议包含的内容

建议优先提炼以下内容：
- 当前业务目标
- 当前核心角色
- 当前主要模块
- 当前主流程
- 当前关键规则
- 本次可能受影响的范围
- 明确不改动的范围
- 待确认项

可直接参考：`references/current-state-summary-template.md`

## 5. 输出边界

### 允许写入新 PRD 的内容
- 对现状的摘要性概括
- 与本次需求直接相关的现有规则
- 为说明设计取舍所必需的背景信息

### 不建议写入新 PRD 的内容
- 参考 PRD 的整段复制
- 与本次需求无关的历史模块说明
- 旧文档里的冗余章节
- 技术实现细节的机械搬运

## 6. 推荐文件命名

- `current-state-summary.md`
- `xxx-new-prd.md`
- `xxx-change-prd.md`

例如：
- `knowledge-tag-current-state-summary.md`
- `knowledge-tag-new-prd.md`
- `approval-workflow-change-prd.md`
